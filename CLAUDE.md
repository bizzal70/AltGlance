# AltGlance

All your characters at a glance: level, gold, where they are, rested experience, professions and bag space. One addon, one repository: `bizzal70/AltGlance`.

## Workflow

- **No local `.git`.** GitHub holds all history. Publish with `tools\Publish.ps1 -Message "..."`, which uses a throwaway temp clone and runs the tests first.
- **Layout:** the addon's own files (`AltGlance.toc` and the Lua files) sit at the top of the project, because that is what the release packager expects. `tests/`, `tools/` and `.github/` are development-only and are left out of the released zip by `.pkgmeta`.
- **Testing in game:** `tools\Link-Addon.ps1` junctions this folder into the client's `Interface\AddOns` as `AltGlance`. Edits are live after `/reload`; a new file or a TOC change needs a full client restart.
- **Client install:** `C:\Program Files (x86)\World of Warcraft\_forever_\` (`Wow.exe`, product `wowf`), the live client since launch (4 November 2026). The beta folder `_classic_beta_` was removed on 2026-11-02, and its saved data went with it.
- **Tests:** `python tests/run.py` runs the addon in real Lua 5.1 (the `lupa` pip package) against a fake WoW API in `tests/wow_stub.lua`, loading the files the TOC lists. The tests run before every publish and again on GitHub. They prove the addon's own logic only; whether the real client behaves like the stub can only be checked in game. Three earlier bugs in sibling addons were wrong assumptions about the game that the fake shared, so anything that calls a game function for the first time is wrapped so a surprise cannot put an error on screen.
- **Releases:** a tag starting with `v` runs `.github/workflows/release.yml`, which uses the BigWigs packager (it recognises this client and builds `-forever.zip` as game version 1.60.1). CurseForge and Wago uploads are skipped until their project IDs are in the TOC and their tokens are in the repository secrets.
- **This repository may be made public.** Keep character names, account details and machine-specific paths out of it.

## How it works

- One record per character in `AltGlanceDB.chars[guid]`, account-wide (`SavedVariables`, not per-character): name, realm, class, faction, level, money, zone, xp, xpMax, rested, resting, professions, bagFree, bagTotal, seen.
- `ns.Snapshot` rewrites the current character's record on login and on the events in `REFRESH_EVENTS` (money, level, experience, resting, zone, skills, bags, logout). Each field is only overwritten when the game gives a usable value, so something withheld for a moment does not erase what was known. It runs under `pcall`.
- Rested experience for characters not being played is estimated: 5% of a level per 8 hours when they logged out resting, a quarter of that otherwise, capped at 1.5 levels. Those are the original game's rates and are unverified for Forever; the window marks estimates with `~`.
- `ns.Characters` returns proxies over the saved records (so `key` and `isCurrent` are never written to the saved data), sorted by `sortBy` / `sortDescending`.
- Professions are read with `GetProfessions` / `GetProfessionInfo`, which GatherLog confirmed works on Forever. Free bag slots come from `C_Container.GetContainerNumFreeSlots` over bags 0 to 4.
- `Items.lua` ("On my alts", 0.5.0): `record.bagItems` / `record.bankItems` = { [itemID] = count } per character, `record.bankSeen`, and account-wide `AltGlanceDB.itemLinks[itemID]` (for names and clickable links in `/alts find`). Bags (0-4, plus `Enum.BagIndex.ReagentBag` if present) are read on `BAG_UPDATE_DELAYED`; the bank only while open (`BANKFRAME_OPENED`/`CLOSED`, or `PLAYER_INTERACTION_MANAGER_FRAME_SHOW`/`HIDE` with `Enum.PlayerInteractionType.Banker`), its containers taken from `Enum.BagIndex` names (Bank, Reagentbank, BankBag_*, CharacterBankTab_*) or else -1 and 5-11. A read that sees no slots at all, or any secret value, is discarded. Tooltips via `TooltipDataProcessor.AddTooltipPostCall(Enum.TooltipDataType.Item)` on GameTooltip and ItemRefTooltip only, falling back to `OnTooltipSetItem`. Which bank containers Forever uses is unverified (2026-11-17).
- `Planner.lua` (0.8.0, profession planner): recipes read while a profession window is open (TRADE_SKILL_SHOW / LIST_UPDATE / DATA_SOURCE_CHANGED / UPDATE, NEW_RECIPE_LEARNED; 0.5 s debounce) via `C_TradeSkillUI` (GetBaseProfessionInfo, GetAllRecipeIDs, GetRecipeInfo.learned, GetRecipeSchematic(id, false).reagentSlotSchematics: required basic slots, reagents[1].itemID, quantityRequired; outputItemID), falling back to the classic GetNumTradeSkills / GetTradeSkillReagentInfo API; skips linked/guild/NPC professions. Saved as `AltGlanceDB.recipes[charKey][profession] = { seen, list }`. Makeable counts use `record.bagItems` + `bankItems`; alts count only on the crafter's realm and faction (crafter's fullName known). Plan: `AltGlanceDB.plan = { to, items = { name, profession, count } }`; `ns.PlanWants(itemID)` drives the "planned" mail kind (only when the panel's target is the crafter and the crafter is short); on MAIL_SHOW `OfferPlan` points `mailTo` at the crafter. `/alts prof debug` prints what the API gives. 0.8.1 Craft: `ns.CraftState`/`ns.Craft` use `C_TradeSkillUI.CraftRecipe(recipe.id, min(wanted, GetRecipeInfo.numAvailable))` (classic: DoTradeSkill(index)), only for the logged-in crafter with that profession open (`ns.openProfession`, set by ReadRecipes, cleared on TRADE_SKILL_CLOSE), not in combat; otherwise `OpenTradeSkill(book.skillLine)` (base.professionID). Whether Forever's profession window uses C_TradeSkillUI as in Retail is unverified (2026-11-19).
- Quest materials (0.9.0, `Mail.lua`): `ns.QuestNeeds()` reads item objectives from the quest log (`C_QuestLog.GetNumQuestLogEntries/GetInfo/GetQuestObjectives`, type "item", numRequired; fallback GetNumQuestLeaderBoards/GetQuestLogLeaderBoard) and matches by item name parsed from "4/6 Name" or "Name: 4/6". `ns.MaterialsToSend()` keeps whole stacks of a needed item, in bag order, until they cover the number required, and returns what it kept as a second value (shown as `panel.questNote`). Unverified in game: the objective text format on Forever.
- Realm (0.9.1): Forever's `GetRealmName()` returned "" on one character (2026-11-22; others had "CAMWOW US1 Realm 10 RP"), which broke CanMail/bank alt matching. Never save "" (`ReadRealm` also tries GetNormalizedRealmName and UnitFullName); compare realms only through `ns.SameRealm(keyA, a, keyB, b)` (GUID server number "Player-<server>-<id>" when both have one; seen: 6927 = Realm 9, 6928 = Realm 10) and name bank-alt groups with `ns.RealmOf(key, record)` (the realm name most characters on that server number were saved with). 0.9.1 still failed in game: the fallback name read on that character evidently differed.
- Record button (0.10.0, `Planner.lua`): `ns.UnrecordedProfessions()` lists the player's GetProfessions entries (GetProfessionInfo 7th return = skillLine) not in `recipes[key]`, skipping skill lines 182/393/356/794 and `AltGlanceDB.recordTried[key][name]`. `ns.RecordProfessions()` queues them: `C_TradeSkillUI.OpenTradeSkill(skillLine)`, then up to 10 half-second looks calling `ns.ReadRecipes` once a TRADE_SKILL_* event says a window opened, then `CloseTradeSkill`, then the next. Window never opened: stop and say so (OpenTradeSkill from a timer, without a click, may be refused; unverified in game). Opened but nothing read: marked in recordTried.
- `Mail.lua` (0.6.0): the Send materials panel beside MailFrame (MAIL_SHOW/MAIL_CLOSED). Recipients: other characters with the same realm and faction. Kinds: Trade Goods (class 7) subclasses Metal & Stone 7, Herb 9, Leather 6, Cloth 5, plus "Gear to disenchant" (weapon 2 / armour 4, quality 2-4, not isBound; off by default). Sends 12 attachments per mail (PickupContainerItem + ClickSendMailItemButton, then SendMail), the next after MAIL_SEND_SUCCESS (+0.5 s); stops on MAIL_FAILED or MAIL_CLOSED, if items are already attached, or if postage exceeds money. Bank alt: `AltGlanceDB.bankAlt["Realm|Faction"] = key`; `SendMailNameEditBox` filled when empty on MAIL_SHOW, SendMailFrame OnShow and after an ordinary MAIL_SEND_SUCCESS. Whether chained SendMail works without a fresh click in Forever is unverified (2026-11-17); if not, the Send button sends the rest.
- Money shows the game's coin icons through `C_CurrencyInfo.GetCoinTextureString` where available, otherwise as text.
- Not run in the real game when written (2026-10-13). Characters on Forever have a first and last name; what `UnitName` returns for them is unverified.

## Client facts

Everything below, unless marked verified, comes from community sources during the beta (Warcraft Wiki, GitHub ports, fan guides), not from Blizzard docs. Builds change. Verify in game before relying on any of it.

- Local client was 1.60.1.70338 on 2026-10-11 (beta, `WowB.exe`); the live client is 1.60.1.70707 (2026-10-30, `_forever_\Wow.exe`). The TOC interface number for live is not yet confirmed; check `select(4, GetBuildInfo())` in game.
- TOC: `## Interface: 16001` (verified in game on build 70338).
- TOC flavor suffix is `_Forever.toc` or `_Camelot.toc`. The TOC `[Game]` variable expands to `Camelot`. Game type for `AllowLoadGameType` is `forever` / `camelot`.
- The client is Retail-based: Midnight 12.x API and UI architecture, not the Classic API. Port from Retail code.
- `WOW_PROJECT_ID` is `18` on build 70338 (verified in game 2026-10-11, along with interface 16001, by a starter addon since removed). Community guides written against earlier builds say it is 1 (`WOW_PROJECT_MAINLINE`); that is out of date, so Retail code gated on `WOW_PROJECT_ID == WOW_PROJECT_MAINLINE` will not run here. The name of the constant for 18 is not yet known. Prefer testing for the specific API you need over branching on either number.
- Lua 5.1: no `goto`, no `//`, no bitwise operators (use `bit.band` etc.), no `require`. The TOC is the module loader. Start files with `local addonName, ns = ...`.
- Removed globals: `GetItemInfo`, `GetSpellInfo`, `UnitAura`/`UnitBuff`/`UnitDebuff`, `GetTalentInfo`, `GetNumTalentTabs`, `CombatLogGetCurrentEventInfo`, `InterfaceOptionsFrame_OpenToCategory`. Use `C_Item`, `C_Spell`, `C_UnitAuras`, `C_Traits`, and the `Settings` API.
- `C_Spell.GetSpellInfo` returns a table. Item and spell data can be nil until cached.
- Registering an event that does not exist throws and aborts the file. Wrap speculative `RegisterEvent` calls in `pcall`.
- Secret values (Midnight combat restrictions) are active. In combat, `UnitHealth`, aura data, and some names and booleans can be secret: arithmetic, comparison, and printing fail. Guard with `issecretvalue`, and pass values straight to widgets (`StatusBar:SetValue`, `Cooldown:SetCooldownFromDurationObject`) instead of doing Lua math. Combat-log parsing is not available.
- Check `InCombatLockdown()` before touching protected frames and defer to `PLAYER_REGEN_ENABLED`.
- SavedVariables: initialise in `ADDON_LOADED`. Early beta builds reportedly wrote them but did not read them back; on build 70338 they are read back (confirmed in game 2026-10-11).
- Renamed from AltBoard to AltGlance on 2026-11-08 (0.2.0), because "Allemano AltBoard" (CurseForge 1719158, Forever) installs into an `AltBoard` folder and uses `/altboard`. Saved data moved from `AltBoardDB` to `AltGlanceDB`; the user's WTF file was copied over by hand. `/alts` kept, `/altboard` replaced by `/altglance`.
